# cli.notify Implementation Milestones

## Goal

Implement a Bashly-generated `cli.notify` executable that exposes `backlight` and `sound` namespaces, normalizes the current percent value for each action, and forwards the resulting request to Lucent for GTK4 shell-layer icon notification rendering.

## Current state

```txt
bashly.sh:
  src/cli.notify/src/bashly.yml is a placeholder stub
  no notify namespace tree yet
  agent-sdk profile exists under agent-sdk/cue/profiles/bash-cli/
  generated project surface currently includes meta/agent/generated/project-graph.json

dotfiles:
  Hyprland binds exist in the dotfiles tree
  Lucent config exists at private_dot_config/lucent/config.toml
  Hyprland Lucent layer policy exists in modules/notifications.lua
```

## Target state

```txt
cli.notify:
  generated by Bashly
  linked into the user command path
  invoked by Hyprland binds
  exposes backlight and sound namespaces
  accepts up/down on each namespace
  normalizes current percent before handoff
  forwards icon notification requests to Lucent
  lets Lucent format the GTK4 shell-layer surface
```

## Constraints

- CUE/schema first.
- Bashly generated output is reproducible and not hand-edited.
- Shell source owns behavior; generated Bashly output is evidence only.
- Agent workflow lives in `agent-sdk/cue/profiles/bash-cli/`.
- `cli.notify` does not call external mutator executables.
- `cli.notify` does not render notifications itself.
- Lucent owns notification formatting and rendering.
- Hyprland owns binds and layer rules.
- Stable dotted executable convention: `cli.<domain>`.

## Milestone 6: Implement Lucent handoff

### Deliverables

Implement the transport boundary in `src/cli.notify/src/lib/lucent.sh` so the request reaches Lucent with enough metadata for GTK4 shell-layer formatting.

Request shape:

```txt
namespace
action
percent
summary
body
icon
transient
```

Rules:

- Lucent formats the notification surface.
- `cli.notify` does not format GTK widgets or shell-layer surfaces.
- Repeated events update the same namespace key.

### Exit criteria

```txt
Backlight and sound requests are handed off to Lucent with stable namespace keys.
```

## Milestone 7: Wire Hyprland binds

### Deliverables

Patch the dotfiles bind module to call `cli.notify` namespaces.

Target replacements:

```lua
hl.bind("XF86MonBrightnessUp", hl.dsp.exec_cmd("cli.notify backlight up"), {
  repeatable = true,
})

hl.bind("XF86MonBrightnessDown", hl.dsp.exec_cmd("cli.notify backlight down"), {
  repeatable = true,
})

hl.bind(
  "XF86AudioRaiseVolume",
  hl.dsp.exec_cmd("cli.notify sound up"),
  { locked = true, repeatable = true }
)

hl.bind(
  "XF86AudioLowerVolume",
  hl.dsp.exec_cmd("cli.notify sound down"),
  { locked = true, repeatable = true }
)
```

### Exit criteria

```txt
Hyprland reloads cleanly.
XF86 brightness/audio keys update state and trigger Lucent rendering.
Notifications do not stack during repeated keypresses.
```

## Heads-up

Expected friction points:

- Bashly behavior with a dotted executable name should be verified early.
- Namespace update-by-key behavior must be stable for repeated binds.
- Lucent formatting behavior is the presentation boundary and should remain isolated.
- Current-percent normalization may vary slightly across host state sources.
- Hyprland repeated binds can emit faster than Lucent updates the rendered notification.

## Definition of done

```txt

Generated Bashly output is not manually edited.
```
