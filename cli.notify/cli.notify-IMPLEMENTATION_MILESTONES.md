# cli.notify Implementation Milestones

## Goal

Implement a Bashly-generated `cli.notify` executable that bridges Hyprland key binds to libnotify notifications and exposes Lucent/Freedesktop notification-server data through normalized JSON.

## Current state

```txt
bashly.sh:
  cli.notify/stub exists
  no notify Bashly command tree yet
  CUE authority graph exists for repo/agent workflow
  validation contract is shellharden -> shfmt -> shellcheck source -> bashly generate

dotfiles:
  Hyprland binds directly call brightnessctl/wpctl
  Lucent config exists at private_dot_config/lucent/config.toml
  Hyprland Lucent layer policy exists in modules/notifications.lua
```

## Target state

```txt
cli.notify:
  generated by Bashly
  installed/projected into the user command path
  invoked by Hyprland binds
  wraps brightnessctl and wpctl
  emits replaceable libnotify notifications
  reads org.freedesktop.Notifications server data
  reports Lucent status as JSON
```

## Constraints

- CUE/schema first.
- Bashly generated output is reproducible and not hand-edited.
- Shell source owns behavior; generated Bashly output is evidence only.
- No long-running daemon.
- No Lucent lifecycle manager.
- No compositor-specific rendering logic inside `cli.notify`.
- Hyprland owns binds and layer rules.
- Lucent owns notification rendering via D-Bus activation.
- D-Bus status commands must work even if the active notification server is not Lucent.
- Stable dotted executable convention: `cli.<domain>`.

## Milestone 4: Implement libnotify send path

### Deliverables

Implement:

```txt
cli.notify send
```

Required flags:

```txt
--summary TEXT
--body TEXT
--channel NAME
--icon ICON
--urgency low|normal|critical
--timeout-ms INT
--transient / --no-transient
--replace / --no-replace
--json
```

Behavior:

- Use `notify-send` as the primary libnotify client.
- Use `--print-id` and `--replace-id` when available.
- Persist notification IDs by channel under `${XDG_RUNTIME_DIR}/cli.notify/ids/`.
- Degrade to fire-and-forget if ID replacement is unavailable.
- Return structured JSON when `--json` is passed.

### Exit criteria

```sh
cli.notify send --summary "cli.notify" --body "first" --channel test --json
cli.notify send --summary "cli.notify" --body "replace" --channel test --json
```

Expected:

```txt
Second call replaces or attempts to replace the first notification.
JSON reports whether replacement was used.
```

## Milestone 8: Implement Lucent derived status

### Deliverables

Implement:

```txt
cli.notify lucent status --json
cli.notify lucent config --json
```

Derived status fields:

```json
{
  "ok": true,
  "service": "org.freedesktop.Notifications",
  "server_available": true,
  "server_name": "Lucent",
  "is_lucent": true,
  "activation_file_exists": true,
  "config_path": "${XDG_CONFIG_HOME}/lucent/config.toml",
  "config_exists": true
}
```

Rules:

- Do not assume Lucent owns the bus.
- Detect active server from D-Bus server information.
- Treat another daemon as a valid diagnostic state, not an automatic command failure.
- Keep activation-file and active-owner checks separate.

### Exit criteria

```sh
cli.notify lucent status --json
cli.notify lucent config --json
```

Expected:

```txt
If Lucent owns org.freedesktop.Notifications, is_lucent=true.
If another daemon owns it, is_lucent=false and status explains what owns the service.
```

## Milestone 9: Wire Hyprland binds

### Deliverables

Patch the dotfiles bind module from direct mutation commands to `cli.notify` commands.

Target replacements:

```lua
hl.bind("XF86MonBrightnessUp", hl.dsp.exec_cmd("cli.notify brightness up"), {
  repeatable = true,
})

hl.bind("XF86MonBrightnessDown", hl.dsp.exec_cmd("cli.notify brightness down"), {
  repeatable = true,
})

hl.bind(
  "XF86AudioRaiseVolume",
  hl.dsp.exec_cmd("cli.notify volume up"),
  { locked = true, repeatable = true }
)

hl.bind(
  "XF86AudioLowerVolume",
  hl.dsp.exec_cmd("cli.notify volume down"),
  { locked = true, repeatable = true }
)

hl.bind("XF86AudioMute", hl.dsp.exec_cmd("cli.notify volume mute"), {
  locked = true,
})
```

### Exit criteria

```txt
Hyprland reloads cleanly.
XF86 brightness/audio keys mutate state and emit Lucent notifications.
Notifications do not stack during repeated keypresses.
```

## Heads-up

Expected friction points:

- Bashly behavior with a dotted executable name should be verified early.
- `notify-send` feature variance across libnotify versions.
- Notification-server differences around timeout, hints, persistence, and replacement behavior.
- D-Bus activation can fail if the service file is missing or another daemon already owns `org.freedesktop.Notifications`.
- Hyprland repeated binds can emit faster than the notification server returns IDs.
- `wpctl get-volume` formatting may vary slightly across PipeWire/WirePlumber versions.
- `brightnessctl -m` may report different device names and units across hardware.

## Definition of done

```txt
cli.notify is generated by Bashly.
Hyprland binds call cli.notify instead of raw wpctl/brightnessctl.
Volume and brightness notifications replace by channel.
cli.notify dbus info --json reports the active notification server.
cli.notify lucent status --json correctly identifies whether Lucent owns the bus.
just source-check remains green.
Generated Bashly output is not manually edited.
```
